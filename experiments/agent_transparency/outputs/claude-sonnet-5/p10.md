# Health Clinic Triage Chatbot

Before the code — three things that matter more than the implementation:

> ⚠️ **This is decision-support software, not a medical device or diagnostic tool.** The symptom logic included here is a *starting template* written by an engineer, not a clinician. **A licensed clinician (ideally your Medical Director) must review, edit, and formally sign off on every question and outcome before this goes live**, and it should be re-reviewed on a schedule (e.g., annually or after any incident).
>
> ⚠️ **Design principle used throughout:** every category checks for red flags *first*, free text can only ever escalate urgency (never decide it's safe), and the system defaults to the *more urgent* outcome whenever it's unsure. "When in doubt, refer up."
>
> ⚠️ **There must always be a human fallback** (a phone number to a nurse triage line / front desk) shown at every step, and an always-visible "this might be an emergency" button that bypasses the whole flow.

I built the app around a **deterministic, auditable rules engine** (JSON decision trees) rather than having an LLM freestyle medical reasoning. This is safer, testable, and — critically — something your clinical and legal team can actually read and approve line by line.

## Architecture

```
triage-chatbot/
├── backend/
│   ├── src/
│   │   ├── rules/
│   │   │   ├── triageRules.json      # clinician-editable decision trees
│   │   │   └── ruleEngine.ts         # deterministic tree walker
│   │   ├── store/sessionStore.ts     # session state (swap for Redis in prod)
│   │   ├── audit/auditLog.ts         # append-only audit trail
│   │   ├── routes/triage.ts          # REST API
│   │   ├── types.ts
│   │   └── server.ts
│   ├── tests/ruleEngine.test.ts
│   ├── package.json / tsconfig.json
└── frontend/
    ├── src/
    │   ├── api/triageApi.ts
    │   ├── components/{ChatWidget,Disclaimer,OutcomeCard}.tsx
    │   ├── App.tsx
    │   └── styles.css
    └── package.json
```

Flow: **consent & disclaimer → emergency keyword scan (always on) → pick a category → walk a clinician-authored yes/no tree → deterministic outcome (EMERGENCY / URGENT / SAME_DAY / ROUTINE / SELF_CARE) → clear call-to-action + human escalation.**
